# android-emu

Нативное приложение на **C# / WinForms** для Windows x64. Устанавливает Android из ISO на виртуальный диск QEMU, запускает Android и позволяет устанавливать APK через ADB. **ARM-приложения работают через Native Bridge внутри x86/x86_64 Android**, а не через отдельную ARM-виртуальную машину.

[Скачать релиз для Windows x64](https://github.com/gladok1123/android-emu/releases/latest)

## Быстрый старт

1. Установите [QEMU для Windows x64](https://www.qemu.org/download/#windows). Нужны `qemu-system-x86_64.exe` и `qemu-img.exe` из одной поставки. Для ускорения нужна сборка QEMU с WHPX.
2. Скачайте [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) и распакуйте каталог целиком. Они нужны для APK и диагностики ARM, но не для установки Android.
3. Откройте `android-emu.exe`. Если инструменты не найдены автоматически, на вкладке **Настройки** выберите `qemu-system-x86_64.exe` и `adb.exe`, затем нажмите **Сохранить настройки**.
4. На вкладке **Android** укажите размер диска и нажмите **Установить из ISO…**. Выберите установочный x86/x86_64 ISO для ПК с загрузкой Legacy BIOS (например, подходящую сборку Android-x86 или Bliss OS). ISO для ARM, образы телефонов, AVD и UEFI-only ISO не поддерживаются.
5. В окне QEMU выберите **Installation**, установите Android на единственный виртуальный диск и установите загрузчик для Legacy BIOS. Физические диски компьютера не подключаются, ISO доступен только для чтения. После установки выключите гостя или закройте окно QEMU и подтвердите сохранение диска. Нажмите **Запустить Android** для загрузки с QCOW2 без ISO.
6. В запущенном Android включите отладку ADB по сети на **TCP 5555** и подтвердите авторизацию, если гостевая система её запросит. Название настройки зависит от сборки. Пункт «Беспроводная отладка» с динамическим портом и спариванием в некоторых сборках Android 11+ — не то же самое, что ADB на фиксированном порту 5555.
7. На вкладке **Приложения** нажмите **Установить и открыть APK…**. Можно также обновить список сторонних приложений в госте и открыть одно из них.

Требуется Windows 10/11 x64 и **.NET Framework 4.8** или новее (не путать с .NET Desktop Runtime). Он уже есть в Windows 11 и современных версиях Windows 10; при отсутствии установите [из Microsoft](https://dotnet.microsoft.com/download/dotnet-framework/net48). QEMU, ISO, Platform-Tools и библиотеки-трансляторы в релиз не входят.

## ARM APK

Выберите x86/x86_64 систему с уже включённым **Native Bridge** (`libndk_translation` или `libhoudini`). Его наличие, настройка и список ABI зависят от конкретной сборки Android. На вкладке **Диагностика** запустите **Проверить ARM**: статус `arm64-v8a`, `armeabi-v7a` и `armeabi` берётся из гостя. Наличие файла переводчика само по себе не означает, что ABI доступен.

При установке лаунчер сравнивает библиотеки из `lib/<ABI>/*.so` в APK с ABI Android. Если ни один не совпадает, он объясняет причину и не отправляет APK в гостя. Наличие ARM64 **не гарантирует** работу ARM32. Даже совпадающий ABI не гарантирует совместимость конкретного приложения (могут быть ограничения транслятора, Android API, графики или Play Integrity). Поддерживаются одиночные `.apk`, не наборы `.apks`/`.xapk` и не split APK, требующие дополнительных частей.

## Windows Hypervisor Platform

На вкладке **Диагностика** нажмите **Включить Windows Hypervisor Platform…**. Приложение запрашивает UAC только для системного DISM и включает компонент `HypervisorPlatform` с `/NoRestart`. Никаких других компонентов Hyper-V и автоматической перезагрузки приложение не запрашивает.

Если DISM потребовал перезагрузку, выполните её вручную. Для WHPX должна быть включена виртуализация VT-x/AMD-V в BIOS/UEFI; приложение проверяет доступность Windows Hypervisor API, а не наличие службы. При ошибке старта с WHPX QEMU повторяет запуск с программной эмуляцией TCG; текущий режим показан в шапке. Можно выбрать постоянный TCG в **Настройках**. WHPX не добавляет ARM-трансляцию в Android.

## Данные и диагностика

- Настройки и диски хранятся в `%LOCALAPPDATA%\android-emu\winforms`. Данные версии v0.2.0 не изменяются.
- Каждый ISO устанавливается на новый QCOW2-диск. Его размер на хосте растёт по мере записи гостем.
- В **Диагностике → Журналы** доступны команды запуска QEMU и вывод ошибок. Там же отображается адрес ADB; проброс доступен только на `127.0.0.1` хоста.
- Если Android запускается, но ADB не подключается, проверьте поддержку сетевой отладки у образа, TCP 5555 и авторизацию. Установщик ISO запускается без сетевого доступа и без ADB; APK устанавливаются после загрузки с диска.
- Если установщик не загружается или не видит виртуальный диск, проверьте поддержку Legacy BIOS, SATA/AHCI и требования конкретной сборки ISO. Выбор раздела и установка загрузчика выполняются в установщике Android; лаунчер их не автоматизирует.

## Сборка

На Windows с .NET SDK, MSBuild и **.NET Framework 4.8 Developer Pack**:

```powershell
.\scripts\build-windows.ps1
```

Скрипт собирает приложение в Release, запускает проверки и записывает `dist\android-emu.exe` и `dist\SHA256SUMS.txt`. Нет внешних NuGet-зависимостей. Проверки покрывают сохранение настроек, параметры QEMU для ISO/диска, команды ADB, разбор ABI и коды DISM. Для ручной проверки на Windows: установить подходящий ISO, загрузить его с диска без ISO, проверить ARM64/ARM32 в **Диагностике**, установить APK для доступного ABI и проверить UAC и запуск с WHPX после перезагрузки.
